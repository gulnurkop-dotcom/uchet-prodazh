# PRD: Автоматизированный учёт продаж в Excel / Google Таблицах

| | |
|---|---|
| **Версия** | 1.0 |
| **Дата** | 03.10.2026 |
| **Статус** | Реализован первый релиз (файл `uchet_prodazh.xlsx`) |
| **Формат решения** | Книга Excel (.xlsx), совместима с Google Таблицами |

---

## 1. Контекст и проблема

Заказчик ведёт учёт продаж в Excel или Google Таблицах и хочет автоматизировать его целиком: ввод продаж и остатков, отчёты и аналитику, выставление счетов клиентам.

Проблемы ручного учёта в таблицах:

- данные вводятся повторно (название, цена, сумма набираются вручную);
- остатки товара приходится считать отдельно;
- отчёты по месяцам, товарам и клиентам собираются вручную;
- счета клиентам оформляются отдельно от журнала продаж, что приводит к расхождениям.

## 2. Цели

1. Свести ручной ввод к минимуму: пользователь вводит только первичные данные (кто, что, сколько, когда).
2. Получать актуальные остатки и сигнал о необходимости заказа без отдельных расчётов.
3. Получать отчёты по выручке, прибыли и марже автоматически.
4. Формировать счёт клиенту из уже внесённых продаж.
5. Остаться в привычной среде (Excel / Google Таблицы), без внедрения новых систем.

### Не цели (первый релиз)

- Многопользовательская работа с разграничением прав.
- Интеграция с бухгалтерскими системами (1С и др.), банками, кассами.
- Автоматический приём заказов из форм и мессенджеров.
- Налоговый учёт (НДС и прочее) и юридически значимые печатные формы.

## 3. Пользователи

| Роль | Что делает |
|---|---|
| Владелец / менеджер | Вносит продажи и приходы, смотрит отчёты, печатает счета |
| Небольшая команда | Использует тот же файл как единый журнал (по очереди или через Google Таблицы) |

Предполагается, что пользователь уверенно работает с таблицами, но не программирует.

## 4. Допущения и ограничения

- Исходное состояние: учёт ведётся в Excel или Google Таблицах (подтверждено заказчиком).
- Объём автоматизации: всё сразу (ввод, отчёты, документы).
- Валюта: тенге (₸), так как пользователь находится в Астане. Меняется форматом ячеек.
- Цена продажи берётся из справочника товаров. При смене цены пересчитываются и прошлые продажи. Для фиксации цены на момент продажи её нужно перезаписать вручную в строке.
- Один счёт состоит из нескольких строк журнала с одинаковым номером счёта, максимум 20 позиций на счёт.
- Ёмкость формул: 999 строк продаж, 999 строк прихода, 199 товаров, 199 клиентов. В отчёте по товарам и клиентам показываются первые 30 записей справочника.
- Функции только совместимые с Excel 2007+ и LibreOffice (без `XLOOKUP`, `FILTER`, `SORT` и подобных).

## 5. Функциональные требования

### 5.1 Структура книги

| № | Лист | Назначение |
|---|---|---|
| 1 | Инструкция | Описание работы с файлом, допущения |
| 2 | Продажи | Журнал продаж, главный лист ввода |
| 3 | Товары | Справочник товаров и автоматические остатки |
| 4 | Приход | Журнал поступлений товара |
| 5 | Клиенты | Справочник клиентов и сводка по ним |
| 6 | Отчет | Аналитика по месяцам, товарам, клиентам, график |
| 7 | Счет | Печатная форма счёта на оплату |

**Соглашение по оформлению:** жёлтые ячейки с синим текстом вводит пользователь; остальные ячейки содержат формулы и не редактируются. Шрифт Arial.

### 5.2 Лист «Продажи»

**Ввод пользователем:** дата, № счёта, клиент (выпадающий список из «Клиенты»), артикул (выпадающий список из «Товары»), количество.

**Вычисляется автоматически:**

| Поле | Логика |
|---|---|
| Название | Подбирается из «Товары» по артикулу; если артикула нет в справочнике, показывает «нет в справочнике» |
| Цена | Цена продажи из «Товары» |
| Сумма | Количество × цена |
| Себестоимость | Количество × закупочная цена |
| Прибыль | Сумма − себестоимость |
| Месяц, Год | Из даты, служат для отчётов |
| Ключ строки | `№ счёта \| порядковый номер позиции внутри счёта`, служит для сборки счёта на листе «Счет» |

Дополнительно: закреплённая шапка, автофильтр.

### 5.3 Лист «Товары»

**Ввод:** артикул, название, цена продажи, закупочная цена, начальный остаток, минимальный остаток.

**Вычисляется:**

| Поле | Логика |
|---|---|
| Приход | Сумма количества из листа «Приход» по артикулу |
| Продано | Сумма количества из листа «Продажи» по артикулу |
| Остаток | Начальный остаток + приход − продано |
| Статус | «Заказать», если остаток ≤ минимального, иначе «ОК» |

Статус «Заказать» выделяется красным цветом (условное форматирование).

### 5.4 Лист «Приход»

**Ввод:** дата, артикул (выпадающий список), количество, поставщик или комментарий. Данные автоматически учитываются в остатках.

### 5.5 Лист «Клиенты»

**Ввод:** название клиента, телефон, email, реквизиты или адрес.

**Вычисляется:** сумма покупок за всё время, дата последней покупки.

Реквизиты клиента подставляются в счёт.

### 5.6 Лист «Отчет»

Параметр: **год** (ячейка B2), по умолчанию 2026.

1. **Помесячная таблица** (январь–декабрь): выручка, прибыль, число проданных позиций, маржа; строка «Итого».
2. **График** «Выручка по месяцам» (столбчатая диаграмма).
3. **По товарам** (за выбранный год): продано штук, выручка, прибыль, место в рейтинге по выручке.
4. **По клиентам** (за выбранный год): число позиций, выручка, место в рейтинге.

### 5.7 Лист «Счет»

- Пользователь вводит номер счёта (B3).
- Автоматически подставляются: дата, клиент, реквизиты клиента, таблица позиций (до 20 строк: №, наименование, количество, цена, сумма) и итог.
- Реквизиты поставщика вводятся вручную (B7) один раз.
- Если счёт не найден, в поле клиента выводится «счёт не найден».
- Настроена область печати и вписывание в одну страницу (A4, портрет). Результат можно распечатать или сохранить в PDF.

## 6. Модель данных и связи

```
Клиенты ──┐
          ├──► Продажи ──► Товары (Продано, Остаток)
Товары ───┘        │            ▲
                   │            │
                   │         Приход
                   ├──► Отчет (по месяцам, товарам, клиентам)
                   └──► Счет (по ключу «№ счёта | позиция»)
```

- Связи построены через `SUMIFS`, `COUNTIFS`, `INDEX` / `MATCH`, `MAXIFS`.
- Справочники («Товары», «Клиенты») являются источниками для выпадающих списков в «Продажи» и «Приход».

## 7. Нефункциональные требования

| Требование | Реализация |
|---|---|
| Нет ошибок в формулах | Пересчёт и проверка выполнены: 9 612 формул, 0 ошибок |
| Все расчёты формулами | Нет жёстко прописанных итогов, при изменении входных данных всё пересчитывается |
| Совместимость | Excel 2007+ и Google Таблицы (загрузить файл на Google Диск и открыть как таблицу) |
| Читаемость | Единый шрифт, цветовая разметка ввода и расчётов, закреплённые заголовки |
| Печать | Лист «Счет» готов к печати на одной странице |

## 8. Критерии приёмки и результаты проверки

| Проверка | Результат |
|---|---|
| Название, цена, сумма, прибыль в «Продажи» подтягиваются по артикулу | Пройдено (например, A-001 × 10 = 150 000 ₸, прибыль 60 000 ₸) |
| Остаток = начальный + приход − продано | Пройдено (например, Товар 1: 50 + 20 − 20 = 50) |
| Итоги по месяцам и общий итог сходятся | Пройдено (тестовая выручка за год 870 500 ₸, прибыль 343 500 ₸) |
| Рейтинги товаров и клиентов считаются | Пройдено |
| Счёт №1001 собирается из двух строк журнала | Пройдено (итого 192 500 ₸) |
| Статус «Заказать» при остатке ≤ минимума | Реализовано через формулу и условное форматирование |

## 9. Тестовые данные

В файле лежат демонстрационные данные: 4 товара, 3 клиента, 8 строк продаж (7 счетов), 3 прихода. Перед использованием их нужно удалить из жёлтых ячеек и внести реальные.

## 10. Риски

| Риск | Влияние | Митигация |
|---|---|---|
| Пользователь перезаписал формулу в расчётных ячейках | Некорректные итоги | Визуальное разделение ячеек ввода и расчёта; при необходимости можно добавить защиту листов |
| Опечатка в артикуле или названии клиента | Нет подстановки данных | Выпадающие списки вместо ручного ввода |
| Изменение цены в справочнике | Пересчёт старых продаж | Задокументировано; можно зафиксировать цену вручную |
| Рост данных свыше заложенных лимитов | Часть данных не попадёт в расчёты | Протянуть формулы вниз; лимиты описаны в инструкции |
| Одновременное редактирование несколькими людьми в Excel | Конфликты версий | Использовать Google Таблицы или вести журнал по очереди |

## 11. Возможное развитие (бэклог)

1. Автоматический приём заказов из онлайн-формы или мессенджера прямо в журнал продаж.
2. Фиксация цены продажи в момент операции (отдельная колонка с историей цен).
3. Защита листов от случайного редактирования формул.
4. Учёт оплат и дебиторской задолженности по клиентам.
5. Учёт НДС и дополнительные печатные формы (накладная, акт).
6. Дашборд на одном экране с ключевыми показателями.
7. Перенос в полноценную систему (учётная программа или веб-приложение) при росте объёма.
